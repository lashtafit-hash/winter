# 😈🩷 PINK CAT — WINTER

Репозиторий новой зимней OG-карточки для Bubble.

## Тебе останется загрузить только фотографию

**Имя файла:** `preview.jpg` (строчные буквы, без пробелов).

**Куда:** в корень репозитория, рядом с `index.html`.

**Рекомендуемый формат:** настоящий JPEG, 1200 × 675 пикселей (16:9), RGB/sRGB. Не просто переименовывать PNG/HEIC — экспортировать как JPEG. Предпочтительный вес до 1 МБ.

**Где загрузить:** на странице репозитория нажми **Add file → Upload files**, выбери `preview.jpg`, затем **Commit changes**.

## Что уже подготовлено

- `index.html`: оформленная зимняя страница, OG и Twitter Card, ссылка на `preview.jpg`.
- `.nojekyll`: отключение обработки Jekyll при публикации через GitHub Pages.

Действующий адрес страницы:
`https://www.winter.watchmecreative.space/`

Прямой адрес фотографии после загрузки:
`https://www.winter.watchmecreative.space/preview.jpg`

**Текущий статус:** собственный домен `www.winter.watchmecreative.space` уже отвечает HTTP 200 с GitHub Pages. DNS указывает на GitHub Pages. `preview.jpg` пока не загружен, поэтому изображение не готово к тесту. Этот путь НЕ проходит через Cloudflare Worker и сам по себе НЕ активирует Telegram-радар. Для сетевого эксперимента использовать отдельный URL Worker после подключения D1 и проверки работы.

## Радар WINTER уже подключён к существующему Worker

**Подключено 21 ноября 2026:** Cloudflare Worker `pinkcat` обслуживает путь
`https://pinkcat.zzyg9ypr55.workers.dev/og/winter.jpg`.

В опубликованном `index.html` поля `og:image`, `og:image:secure_url`, `twitter:image`, `image_src` и видимое изображение страницы используют этот адрес. Worker отправляет отдельное Telegram-уведомление `❄️🩷 WINTER — OG RADAR` при запросах GET/HEAD и затем проксирует исходный JPEG из `https://www.winter.watchmecreative.space/preview.jpg`.

**Загрузка фотографии ещё обязательна:** положить `preview.jpg` рядом с `index.html`. До этого Worker отвечает 502 на запрос фото, хотя сам радар уже принимает обращения. Пробный HEAD-запрос Лиса может вызвать тестовое Telegram-уведомление.

Это **радар обращения к изображению**, а не полноценная запись всех HTML-запросов. Он не способен определить, что запрос пришёл от конкретного артиста. Отдельный Worker+D1 для полноценного forensic-теста пока остаётся в локальном черновике.

## Усиленная фиксация Cloudflare D1 — включена

С 21 ноября 2026 у существующего Worker `pinkcat` появилась постоянная база событий **`pinkcat-og-events`**, а не только Telegram.

**Вариант 1: брендированная ссылка**

`https://www.winter.watchmecreative.space/`

Открытие HTML с GitHub Pages не проходит через наш Worker и **не фиксируется** в D1. Однако запрос OG-картинки из HTML к `https://pinkcat.zzyg9ypr55.workers.dev/og/winter.jpg` уже проходит через Worker и регистрируется как `IMAGE`. Если изображение доставлено другим путём, записи не будет.

**Вариант 2: полноценная диагностическая ссылка**

`https://pinkcat.zzyg9ypr55.workers.dev/probe/winter/PC2026WINTER<UNIQUE>`

Для реальной отправки заменить `<UNIQUE>` на новый уникальный буквенно-цифровой суффикс (не использовать тестовый ID). HTML формируется Worker и содержит `og:image` на том же Worker с параметром `?pc=...`, поэтому в D1 разделены `HTML` и `IMAGE` по одному ID. Метки включают UTC, метод, User-Agent, статус, colo. Записи не включают IP, cookies или содержимое чата. Telegram остаётся дополнительным уведомлением.

**Успешная проверка:** по тестовому ID `PC20261121VERIFY01` D1 сохранила три обращения: HTML HEAD 200, IMAGE HEAD 502 (нет `preview.jpg`), HTML GET 200. До загрузки JPEG отправлять реальный адрес в Bubble нельзя.

Граница наблюдения: ни D1, ни Telegram не видят последующую выдачу фотографии с DearU/CDN, если DearU заранее забрал файл и хранит его у себя. Запросы к нашему Worker также не идентифицируют конкретного артиста.

## Как это связано с будущим Worker

Статическая страница — визуальный эталон. **Для полноценного сетевого теста в Bubble отправляем адрес будущего Worker**, а не прямую ссылку на GitHub Pages. Worker будет отдавать уникальную HTML-страницу `/probe/<ID>`, а OG-картинку — через свой `/image/<ID>.jpg`, записывая отдельно оба события в D1.

Отдельная экспериментальная версия Worker+D1 также сохранена локально на Mac, но для текущей пробы **уже модернизирован действующий `pinkcat`**. Черновик:
`~/Desktop/PINK_CAT/04_ИНСТРУМЕНТЫ_И_ИССЛЕДОВАНИЯ/PINK_CAT_NEXT_PROBE_DRAFT/`.

Для него будет использоваться **исходный JPEG** из этого репозитория:
`https://raw.githubusercontent.com/lashtafit-hash/winter/main/preview.jpg`

В Worker установим:
`IMAGE_SOURCE_URL=https://raw.githubusercontent.com/lashtafit-hash/winter/main/preview.jpg`

Пока **ничего не отправляем** в Bubble, Worker не развёрнут, и события ещё не логируются. Позже перед настоящей отправкой проверим заголовки, изображение, D1 и уникальный ID новой пробы.
